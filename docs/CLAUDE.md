# Documentation Standards

- Use the canonical terms and capitalization from `CONTEXT.md`, and keep normative product decisions consistent with the canonical specification.
- Label normative requirements, implementation descriptions, operator instructions, research findings, and measured evidence distinctly. Instructions describe what to do; only a completed, sanitized artifact may claim that an exercise or measurement occurred.
- Make operator procedures portable and executable: state prerequisites, exact commands, expected results, failure behavior, rollback boundaries, secret handling, and evidence to retain. Cover both direct bundled-Caddy TLS and trusted reverse-proxy topologies where deployment is involved.
- Tie performance and release claims to versioned evidence with revision, environment, fixture, cache state, sample rules, and limitations. Do not generalize an old report to later code.
- Cite primary, version-pinned sources near research claims and distinguish sourced facts from project recommendations.
- Sanitize evidence. Never publish credentials, tokens, private hostnames, email addresses, identities, Media, source paths, search or Comment text, or raw dependency responses.
