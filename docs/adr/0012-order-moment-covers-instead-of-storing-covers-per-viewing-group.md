# Order Moment covers instead of storing covers per Viewing Group

ADR 0011 makes a viewer's Album cover the cover of the earliest Moment they can access, which gives a Curator no way to lead with a later Moment for viewers who can see several. Memento will let a Curator keep an ordered list of preferred Moments per Album, the Cover Order, and each viewer sees the first Moment cover in that order they can access before falling back to the capture-order rule from ADR 0011, so an Album with an empty Cover Order behaves exactly as before. The position belongs to the Moment row, survives cover replacement, split, and sync, and a merge keeps the better position of the two Moments. We considered storing a chosen cover per Viewing Group, the set of People who can see the same Moment covers, which can express one case the order cannot: two groups where one group's Moments are a strict subset of the other's and each should lead with a different Moment both can see. We rejected it because Viewing Groups are derived from Access Decisions and change whenever access, Moments, or People change, so stored per-group choices would need a matching key and a staleness rule, while an order over Moments never goes stale. Viewing Groups remain a Curator-only, never stored preview that shows which cover each group will see for a given order.
