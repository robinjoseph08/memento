# Event and Publication Invariants

- Event drafts, Moments, Staged updates, and Audience review are Curator-private. Recipients read only current published projections and must not learn hidden Moment structure, counts, gaps, or inaccessible ordering.
- Represent Source metadata suggestions per changed field. An unchanged field is null, while a changed field may deliberately suggest an empty value; suggestions never mutate Event metadata without Curator action.
- Use a client-generated Event idempotency identity so retrying draft creation after an uncertain response returns the committed Event instead of creating a duplicate.
- Keep at most one net-coalescing Staged update per published Event or Loose item. Changes that cancel before Publication leave no staged residue.
- Publication is one optimistic, locking transaction that validates every Audience, creates immutable Publication and revision history, replaces exact current placement or Loose projections, entitlement unions, covers, search and activity projections, and appends audit and outbox records. No mixed revision may become observable.
- Every current published placement carries the immutable published Media metadata and source-local capture date used by Recipient gallery and chronology projections. Publication replaces those fields atomically with the placement.
- The complete Event presentation tuple includes title, description, explicit date range, Event Place labels, grouping timezone, selected Event cover preference, flattened Moment and Media order, Moment metadata, and immutable Media metadata. Publish and preview the tuple atomically without deriving Event dates or Event Place labels from hidden Moments.
- Cover selection ranks only authorized and non-withdrawn candidates. Prefer availability first, then the Event selected cover, then the Moment cover, then flattened position and Media identity. A preference is never authority and must never reveal an inaccessible Media identity.
- Loose item Publication uses parallel immutable and current tables rather than making Event placement tables polymorphic. Item authorization is the effective union of current Event and Loose origins, while Event views and archives remain Event-only.
- Preview uses saved editable state and a selected current Recipient generation. It is read-only, allows Pending Recipients, exposes all capabilities as false, writes only preview audit, and is excluded from Recipient authorization and activity.
- Withdrawal removes effective access immediately while preserving identity and history. Loose withdrawal invalidates its reviewed Audience. Restoration requires a freshly reviewed Audience and a later Publication for every stale Event placement or Loose origin. When shared-Media restoration completes, durably requeue each post-Withdrawal origin that advanced earlier so its distinct Audience regains New for you and notification intent.
- Lock order is part of this module's interface. Coordinate Publication, staging, placement, access-generation, Attendance, and Withdrawal locks consistently and cover any change with real concurrency tests.
- Keep rollback injection at named Publication and Withdrawal steps, and test stale versions, retries, reused-Media entitlement unions, and concurrent authorization changes.
